# Successfully Deployed Nextflix: A Netflix Clone on AWS EKS with End-to-End DevOps Automation\n\nThis project wasn’t just about building a clone; it was about understanding how real-world DevOps works at scale. From designing infrastructure to debugging tricky deployment issues, this project delivered deep hands-on learning.\n\n## Project Highlights\n* Built and deployed Nextflix, a Netflix-like streaming app\n* Infrastructure provisioned using **Terraform** on **AWS EKS**\n* **GitOps**-based deployment using **ArgoCD**\n* **CI/CD** pipeline with **Jenkins**\n* Monitoring integrated via **Prometheus** + **Grafana**\n\n## Challenges We Faced & Lessons Learned\n* **Encountered 'Too many pods' error on t3.medium nodes**\n  * **Solution:** Solved by increasing instance size in the managed node group for higher pod capacity.\n* **Terraform 'Unsupported argument' errors due to version mismatch**\n  * **Solution:** Learned to match `terraform-aws-eks` module v21+ with AWS provider ≥ v5.0.0.\n* **ArgoCD and monitoring tools failed to deploy due to pod capacity limits**\n  * **Solution:** Identified the role of CNI, ENI IP limits, and how instance sizing impacts it (resized the instance to t3.xlarge).\n\n**Note:** The Nextflix application is currently not showing static images. Suggestions to correct this are always welcome.\n\n## Key Takeaways\n* Cloud-native projects demand deep attention to infrastructure limits.\n* Scaling isn't just about replicas; it's also about networking and node design.\n* Real DevOps is all about observing, debugging, and iterating.\n\n## Stack Used\n* **Technologies:** Terraform, AWS EKS, Jenkins, ArgoCD, Prometheus, Grafana, GitOps\n* **Application:** Nextflix (custom streaming app)\n\nEvery tool and every error taught something new.
