I am excited to share that I have successfully completed a deep-dive project into Amazon EKS (Elastic Kubernetes Service) using Terraform (IaC). While the final result is a functional 3-Tier "To-Do List" application, the real journey was in the troubleshooting!In this project, I moved beyond local environments to build a scalable, enterprise-grade cloud architecture.## The Architecture*   **Infrastructure as Code:** Leveraged Terraform to provision a custom VPC, Subnets across multiple Availability Zones, and an EKS Control Plane.*   **3-Tier Deployment:** Deployed a Frontend (UI), Backend (API), and Database (MongoDB) using Kubernetes manifests.*   **Traffic Management:** Implemented the AWS Load Balancer Controller to handle external traffic via Ingress.## Real-World Challenges & SolutionsBuilding in the cloud is rarely "plug-and-play." I had to navigate several complex hurdles:1.  **Version Lifecycle Management:** When the original code used a deprecated Kubernetes version (1.25), I successfully upgraded the entire stack to v1.29, resolving provider dependency conflicts and "Dependency Hell" along the way.2.  **EKS Node Group Debugging:** Solved an InvalidParameterException by mapping the correct AMI types to the modern K8s version to ensure worker nodes joined the cluster successfully.3.  **Namespace Isolation:** Implemented logical separation using Kubernetes Namespaces to manage resource organization and security.## Key TakeawaysThis project reinforced that DevOps isn't just about writing code—it’s about understanding the lifecycle of cloud services and being able to bridge the gap between Infrastructure and Application.Special thanks to Vishakha Sadhwani, the community, and the resources that helped me debug these edge cases!I had to make changes to the original repo to get the project working.
