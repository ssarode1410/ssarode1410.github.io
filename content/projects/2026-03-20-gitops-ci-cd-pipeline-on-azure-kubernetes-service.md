I recently spent 6 hours battling pipeline errors, and I wouldn’t trade a single minute of it. Coming from a heavy IT infrastructure background (Windows Servers, VMware), I’ve been diving deep into cloud-native automation. Today, I successfully built and deployed an end-to-end **GitOps CI/CD pipeline** for a multi-tier **microservices application**!\n\n### The Tech Stack\n\n*   **Azure DevOps**\n*   **Azure Kubernetes Service (AKS)**\n*   **Azure Container Registry (ACR)**\n*   **ArgoCD**\n*   **Bash scripting**\n\nAs we all know in DevOps, it’s never just "click and deploy." Here are the two biggest roadblocks I hit and how I solved them:\n\n### Roadblocks & Solutions\n\n#### Bug 1: The Invisible Assassin (`\r: command not found`)\n\nMy Azure Pipeline Linux agent kept choking on a Bash script. The culprit? I wrote the script on my Windows machine, which added hidden CRLF line endings that Linux couldn't read.\n\n**The Fix:** Instead of just fixing the file locally, I hardened the pipeline itself. I added a pre-execution step in my pipeline YAML to install and run `dos2unix` on my scripts. Now, no matter what OS the script is edited on, the pipeline normalizes it automatically.\n\n#### Bug 2: The ImagePullBackOff Heartbreak\n\nArgoCD detected my git commit and triggered the deployment perfectly, but the pods immediately crashed.\n\n**The Fix:** My Bash script was updating the deployment YAML with just the image name (e.g., `votingapp:64`). Because I didn't append the full registry domain, Kubernetes assumed it should pull from the public Docker Hub! I updated my `sed` command to inject the full `.azurecr.io` login path, manually generated an `imagePullSecret` in AKS, attached it to the manifest, and watched the pods turn to a beautiful "Running" state.\n\nA massive shoutout and thank you to Abhishek Veeramalla for his incredible tutorial that served as the foundation for this project. The way you break down complex GitOps concepts is top-tier!\n\nEvery error message is just a stepping stone to a better understanding of the systems we build.\n\nI'm curious—what is the most frustrating, head-scratching pipeline bug you’ve ever had to debug?
